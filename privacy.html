Privacy Policy

Effective date: September 23, 2026.

This policy describes data processing based on the current Void Node architecture. If the actual architecture changes, this policy should be updated.

1. Controller

Operator: Nikita Vitalievich Chetverikov, individual, Russian Federation. Contact: VoidNodeBot@gmail.com. Telegram contact: @clofeLEAN.

2. Data processed

  • Telegram data: chat ID, language, Beginner/Experienced mode, settings, timezone and service state.
  • Portfolio data: assets, balances, prices, portfolio value, allocation, Risk Score, risk factors and analysis history.
  • History: stored analysis results and portfolio snapshots, subject to technical limits.
  • Exchange data: read-only data from supported exchanges. Current integrations include Binance, Bybit, Gate and Kraken.
  • API credentials: API key and secret are encrypted before storage in Redis; the user's original credential message is deleted after receipt.
  • Trade history: when available through a read-only exchange API, recent trades may be used for analytics and Portfolio DNA.
  • Subscription/payment data: plan, activation/end dates, invoice data and related technical identifiers.
  • Referral data: referral code, invitations and awarded bonuses.
  • AI context: portfolio, Risk Score, recent actions, news and relevant conversation history may be sent to an AI provider to generate a response.
  • Anti-scam data: results and technical facts from checks.

3. Purposes

Data is used to operate the Telegram service, connect read-only portfolios, calculate Risk Score, provide analytics, anti-scam checks, news, calendar, AI explanations, alerts, subscriptions, payments, referrals, history and support.

4. Third-party providers

The architecture uses Telegram Bot API, Upstash Redis, Render, ccxt, Binance, Bybit, Gate, Kraken, OpenRouter, CryptoBot/Crypto Pay API, CoinGecko, NewsAPI, Finnhub, Etherscan and DexScreener. Data is shared with a provider only to the extent needed for the relevant function.

5. Storage

Core service state is stored in Upstash Redis. Redis is used as application state storage; individual keys have different technical limits and lifetimes, so not all data has one universal deletion period. The backend is deployed on Render in Ohio, USA. Redis uses Upstash Global.

6. AI

AI is an explanation/context layer, not a trading executor. AI requests may include relevant portfolio information and conversation context needed to answer. AI output is not guaranteed to be accurate.

7. Security

Exchange connections are intended to use read-only permissions. Void Node is not designed to place orders or withdraw funds. API credentials are encrypted before storage. No internet service can guarantee absolute security.

8. International processing

Void Node is available worldwide, so data may be processed by infrastructure and providers in different countries. In particular, the backend is in the United States (Ohio), while Upstash Global may use multiple regions.

9. Retention and deletion

Some data has technical TTLs/limits, while some user state may remain until the relevant keys are deleted or changed. Subject to applicable law, users may request deletion of available data, except where retention is required by law or necessary for security or dispute resolution.
